# 공식 과제 요구사항 vs 기존 Fact Store 계획(Workstream A) — Coverage Gap 분석

> 근거: `미래에셋증권 AI Festival 공식 과제 소개.pdf`(2026.07), `README.md`, `data_filter.md`, `manifest.jsonl`, `universe.csv`, `docs/superpowers/plans/2026-07-29-mvp-fact-store.md`

## 1. 공식 과제 핵심 요구사항 요약

**과제명**: 공시 Agent (Disclosure Analyst) — 공시 데이터를 기반으로 기업 정보를 이해하고, 자연어 질의에 맞는 정보를 검색·분석·설명하는 AI Agent.

**핵심 문구(PDF p.4)**: "단순한 키워드 검색을 넘어, 여러 공시를 종합적으로 이해하고 비교·분석·설명하는 Agent 구현이 핵심"

**Agent 역할 3단계 (PDF p.4)**:
1. 검색 및 정보 추출 — 공시 검색 + 정보 추출(사업·재무·투자·계약·자금조달·지분변동 등)
2. 종합 비교 및 연산 — 종합비교분석(연도별 변화, 기업간 비교) + 계산 기반 질의(증감률·비중) + 변경 이력 분석(정정·후속 공시 연결)
3. 근거 기반 답변 — 공시 내용 근거 자연어 답변 + 환각 방지

**필수 제약**:
- LLM은 **HyperCLOVA X만** 사용 가능 (타 LLM 사용 시 평가대상 제외)
- 제공 코퍼스 외 데이터 사용 금지 (뉴스/리포트/위키 등)
- OpenDART 등 외부 공시 API 실시간 호출 금지
- 답변은 제공된 공시 데이터 근거로 생성, 확인 불가 시 "확인할 수 없음" 명시 필수
- 공시에 근거 없는 미래 예측·투자 의견 생성 금지
- 대상 기업/기간은 주최 측 제공 데이터 그대로 (우리 코퍼스가 정확히 이 범위: 2023.01~2026.03 Q1, 70개사)
- 구현 범위/방식은 자유 (RAG, Vector DB, Re-ranker, GraphRAG, Agent Framework, Function Calling 등)

**제공 데이터 구조 (PDF p.5)**: 공시 원문(정기공시 3종, 수시공시 주요사항보고서+거래소공시, 지분공시) + 구조화 데이터(기업마스터, 공시메타데이터) — 우리 `manifest.jsonl`/`universe.csv`와 정확히 대응.

## 2. 공식 참고 질의 6종 (PDF p.7)

| # | Task 유형 | Closed/Open | 질의 예시 |
|---|---|---|---|
| Q1 | 검색 및 정보 추출 | Closed | "OO기업의 2025년 연결기준 매출액은 얼마인가?" |
| Q2 | 검색 및 정보 추출 | Open | "OO기업의 2026년 1분기 분기보고서를 기준으로 주요 투자 계획을 정리해줘" |
| Q3 | 다중조회 및 비교·연산 | Closed | "2차전지 기업 A와 B 중 2025년 설비투자 규모가 더 큰 기업은 어디인가?" |
| Q4 | 다중조회 및 비교·연산 | Open | "OO기업이 2025년에 실시한 자금조달 내역을 유형별(유상증자, CB, BW, EB)로 정리해줘" |
| Q5 | 복합 문서 추론 | Closed | "OO기업이 2025년에 체결한 주요 계약 이후 해지된 계약이 존재하는가?" |
| Q6 | 복합 문서 추론 | Open | "OO기업의 2023년 사업보고서와 2025년 사업보고서를 비교했을 때 핵심 사업은 어떻게 변화했는지 설명해줘" |

**주의 — 이 문서 전체를 읽을 때 반드시 유지할 전제**: "실제 평가 데이터셋 및 세부 평가기준은 비공개"이므로 위 6개는 **유형을 이해시키기 위한 예시일 뿐**이다. 실제 예선 문제는 상/중/하 난이도 × Closed/Open-ended 조합으로 더 다양하며, **코퍼스 안의 다른 문서/섹션(지분공시, 위험요인, 연구개발활동, 외부평가 등)을 직접 묻는 문제가 나오지 않는다는 보장이 전혀 없다.** 아래 §4의 "6개 참고 질의 매핑"은 "기존 계획이 이 6개 예시에 얼마나 대응하는지"를 보여주는 진단표이지, "6개 외에는 지원하지 않아도 된다"는 뜻으로 읽으면 안 된다 — 그 반대 결론은 `hybrid_architecture_proposal.md` §4에서 명시적으로 교정했다(전체 코퍼스를 최소 범용 RAG 지원 대상에 포함).

## 3. 평가지표 8종 (PDF p.7)

정확성 / 근거완전성 / 요구사항충족 / 근거기반(hallucination) / 추론논리성 / 안전성 및 신뢰성 / 정보한계대응 / (모든 답변에 근거 공시 표시 — 필수 공통 요건).

## 4. `2026-07-29-mvp-fact-store.md` 계획의 실제 커버리지

그 계획(Workstream A 초안)의 대상은 **`doc_group=exchange`의 3개 doc_subtype만** — 신규시설투자등(43) + 단일판매공급계약체결(1106) + 단일판매공급계약해지(20) + 이들의 기재정정. 총 1,169건 = 전체 4,204건의 **27.8%**. `major`(주요사항보고서 598건), `periodic`(정기공시 1,054건), `holding`(지분공시 1,083건)은 라우터/파서 구조(`DartDocumentParser`)는 있으나 표만 chunk화하고, 이 표들에서 특정 fact를 뽑는 label 매핑은 **전혀 없음**.

### 질의별 매핑

| 질의 | 필요 데이터 | 현재 계획 지원 여부 | Gap |
|---|---|---|---|
| Q1 (연결기준 매출액) | `periodic` 사업/분기보고서의 재무제표 표, "연결" vs "별도" 구분 | **미지원** | 재무제표 fact_type/label 없음. "연결" 손익계산서 표를 다른 표들과 구분하는 로직도 없음 |
| Q2 (분기보고서 투자계획 요약) | `periodic` 본문의 서술형 섹션(예: 설비투자현황) | **미지원** | `DartDocumentParser`는 `TABLE`만 순회 — `<P>` 문단을 chunk화하지 않음. 검색 대상 자체가 없음 |
| Q3 (설비투자 규모 비교) | ~~`exchange` 신규시설투자등~~ → **주 경로는 `periodic` II-3. 원재료 및 생산설비** | **가정 자체가 틀렸음 [확인]** | **신규시설투자등 43건은 70개사 중 21개사만 커버하고, 공식 예시가 지목한 2차전지 섹터에서 LG에너지솔루션 0건·삼성SDI 0건이다.** 즉 공식 예시 질문 그 자체를 거래소공시 fact로는 답할 수 없다. 설비투자 질의는 정기공시 서술 섹션 RAG가 주 경로이고 거래소공시 fact는 보조여야 한다 |
| Q4 (자금조달 유형별 정리) | `major` 유상증자/CB/BW/EB 결정 공시의 발행금액·목적 | **미지원 + 전제 오류 [확인]** | (a) `major`의 `doc_subtype`이 **598건 전부 빈 문자열**이라 metadata 필터가 불가 — `report_nm` 파생 subtype 필요. (b) **BW는 코퍼스에 0건**이므로 "BW 발행 내역"의 정답은 "해당 공시 없음"이다. (c) Q4 4종 합계는 82건(13.7%)뿐이고 major 과반(338건)은 자기주식 공시 — 정밀 지원을 Q4에만 맞추면 major 절반 이상이 정밀 경로에서 빠진다 |
| Q5 (계약체결 후 해지 여부) | `exchange` 단일판매공급계약체결/해지의 **계약명** 매칭 | **가장 근접, 확장만 필요** | 금액은 추출되지만 "체결계약명"/"해지계약명" 라벨이 `LABEL_ALIASES`에 없어 계약명 기반 매칭(체결→해지 연결) 로직 자체가 없음 |
| Q6 (사업보고서 연도 비교 서술) | `periodic` 사업보고서의 "사업의 개요" 등 서술형 비교 | **미지원** | Q2와 동일 이유(문단 chunk 부재) + 2개 연도 문서 간 비교·요약은 순수 LLM 요약 레이어(RAG+HyperCLOVA X) 필요, 계획에 전혀 없음 |

### 결론

기존 계획은 6개 참고 질의 예시 중 **정밀 지원(전용 Fact Extractor 수준)으로 명확히 응답 가능한 것이 1개(Q5, 그마저 계약명 매칭 확장 필요)**, 부분 가능이 1개(Q3, 집계 레이어 필요), 나머지 4개(Q1, Q2, Q4, Q6)는 **정밀 지원으로는 대응 불가**. 이는 그 계획이 "거래소공시 3종"이라는 좁은 정밀 지원 범위로 설계됐기 때문이며, 계획 자체의 결함은 아니다.

**진짜 문제는 이 gap표를 "정밀 지원이 없는 항목은 서비스도 안 한다"로 잘못 해석하는 것이다.** 6개 예시 밖의 코퍼스 내용(재무제표 주석, 임원보수, 위험요인, 지분공시 등)도 실제 평가셋에 나올 수 있는 이상, 정밀 지원이 없는 문서·섹션도 **최소한 범용 RAG로는 검색·응답 가능해야 한다.** 그 구조는 `hybrid_architecture_proposal.md` §4(3단계 분류: 정밀 지원/범용 RAG 지원/지원 제한)와 `corpus_coverage_strategy.md`에서 정리한다.

**두 번째 교훈 — 예시를 데이터로 검증하지 않은 채 설계 근거로 쓰지 말 것 [확인]**: 위 Q3·Q4 행에서 드러났듯, 참고 질의 예시를 그대로 "이 데이터로 답한다"고 매핑했다가 실제 코퍼스를 재보니 **예시가 지목한 기업에 그 데이터가 아예 없거나(2차전지 설비투자), 예시가 나열한 항목이 코퍼스에 존재하지 않았다(BW 0건).** 예시는 유형을 알려줄 뿐 데이터 분포를 보증하지 않는다. 모든 정밀 지원 대상은 **착수 전에 manifest로 실제 건수와 기업 커버리지를 세어보고** 결정한다 — 이 원칙은 `corpus_coverage_strategy.md` §0에 실측표로 반영했다.
